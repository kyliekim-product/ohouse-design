# Design Insight — 디자인 크리틱 & 실험 누적 인사이트

오늘의집 PD들의 실제 디자인 판단을 한 곳에 모은 문서. 두 갈래의 소스를 가진다.

1. **크리틱 누적 인사이트** — `#des_pd_design_critique` (PD async design critique 채널) 2024–2025년 스레드에서 Yohan·Ray·Bongho·Luna가 남긴 크리틱 답변 198건을 분류·일반화한 것. 아래 §1.
2. **화면 실험 인사이트** — 각 도메인 `experiments/`의 A/B·UT 결과 중 전사 적용 가치가 있는 것. 아래 §2 (승격 대기 중).

> 모든 인사이트는 **why**(왜 그렇게 판단했는가)와 **일반화 가능한 패턴**에 초점을 둔다. 단발성 결론이 아니라 반복적으로 적용 가능한 기준이다.
> 원문 출처는 본문 말미 **🔗 슬랙 크리틱 링크 인덱스**에서 스레드별로 확인할 수 있다.

## §1. 크리틱 누적 인사이트

### 🔍 [visual] 1. 색은 의도가 분명할 때만 쓴다

- **카테고리**: visual
- **소스**: 크리틱 인덱스 A — Ray·Bongho·Luna (2024-01 ~ 2025-07)
- **신뢰도**: high

#### 발견
색은 "강조하고 싶다"는 막연한 이유로 쓰면 안 된다. **의도가 분명하고, 그 색이 화면에서 그 의도를 실제로 전달할 때만** 쓴다.

#### 근거
- Bongho: "블루 사용은 저희 서비스 전체적으로 블루가 많은 편이라 절제해서 사용했으면 합니다. 블랙이어도 괜찮을 것 같아요." / "레드 컬러가 약간 많아보이는데 레드컬러도 줄일 수 있으면 좋겠다."
- Ray: "배경을 불필요하게 쓰는 걸 최대한 지양하자고 전에 이야기 나눈 것 같아요. 그리고 여기서 배경색을 쓰시면 오히려 '오트밀하우스'라는 볼드 처리된 단어의 contrast는 낮아집니다." / "굳이 오렌지색 쓸 필요 있을까요."
- Luna: "색깔로 구분하는건 여전히 크게 변별력 없을 것 같은데.. 룰과도 맞지 않는 부분이라. 빨강과 파랑으로 색깔로 구분해야하는 이유가 무엇인지 궁금합니다." / 카운트다운 모듈은 "임박한 시간을 레드로 표기하는건 의도를 강조하는것" — 의도가 분명할 때의 정당한 색 사용 사례.

#### 적용 가이드
- 서비스 전체에 이미 흔한 색(오늘의집은 블루)은 절제. 굳이 블루를 쓸 자리면 블랙을 먼저 검토.
- 위계·구분을 색으로 만들지 않는다 — 변별력이 낮고 디자인 룰에 어긋난다 (`principles.md` #4 와 동일).
- 배경색은 오히려 그 위 강조 텍스트의 대비를 떨어뜨린다. 강조가 목적이라면 배경색은 역효과.
- 레드는 "지금 이 정보에 시선을 끌겠다"는 의도가 명확할 때만 (예: 종료 임박 카운트다운).

#### Bad ✕ / Good ✓
- ✕ 로고 배경 brand-blue + 추천 모듈 헤더 blue + CTA blue + 뱃지 blue (한 화면 blue 4곳)
- ✓ 로고 black + CTA brand-blue 1곳 + 다른 강조는 weight·크기로
- ✕ "운영" 메뉴 빨강 / "영업" 메뉴 파랑 (색으로 구분)
- ✓ 동일 형태 + 텍스트 라벨로 구분
- ✕ "오트밀하우스" 위에 노란 배경 박스로 강조
- ✓ "오트밀하우스" weight bold 만으로 강조, 배경 없음

#### 기본 severity 가이드
- 색을 위계·구분 수단으로 쓴 경우 → 🟡 (#9 화면 1순위·#12 일관성과 함께 묶이면 🔴)
- 한 화면 brand color 3곳 이상 → 🟡
- 배경색이 강조 텍스트 대비를 떨어뜨림 → 🟡
- 단순 채도 한 단계 낮추기 의견 → 🟢

#### 한계
브랜드 KV·기획전 등 BX 주도 영역은 별도 가이드를 따른다. 종료 임박·에러 컨테이너 같이 의도가 분명한 색 사용은 예외.

### 🔍 [visual] 2. 뱃지·컴포넌트 형태는 늘리지 않는다

- **카테고리**: visual
- **소스**: 크리틱 인덱스 B — Yohan·Luna·Ray (2024-01 ~ 2024-03)
- **신뢰도**: high

#### 발견
새 케이스가 생길 때마다 새 뱃지·라벨 형태를 만들면 제품 복잡도가 올라간다. **형태는 고정하고, 케이스는 그 안에서 분기**한다.

#### 근거
- Yohan: "최대한 뱃지는 하나의 형태로만 사용하는게 제품의 복잡도를 낮출 수 있을거 같아요."
- Luna: "레드 뱃지는 그레이 뱃지(무료배송), 화이트 뱃지(카드할인)로 변경하여 뱃지 종류 더 추가 하지 않는 방향 고려."
- Ray: 라벨은 형태별로 쓰임을 정의 — "outline stroke로 쓰는 라벨의 경우는 PLP같이 다수로 활용되는 케이스에 적합... black bg를 활용하는 건 단건(화면 전체를 활용하는 리뷰 같은) 페이지에서 강조하기 위한 형태로 사용한다고 정의."

#### 적용 가이드
- 새 표기 니즈가 생기면 새 뱃지를 만들기 전에 기존 형태(그레이/화이트/outline 등)로 흡수할 수 있는지 먼저 본다.
- 형태가 늘어날 수밖에 없다면 **케이스별 사용 정의를 문서로 남긴다** (어떤 맥락에 어떤 형태).
- ODS 승격 기준(`principles.md` #9)과 연결: 5+ 화면 누적 시 표준화.

#### Bad ✕ / Good ✓
- ✕ 무료배송(초록 뱃지) / 오늘출발(보라 뱃지) / 쿠폰(노란 뱃지) / 단독(빨간 뱃지) 4종 컬러 뱃지 동시 노출
- ✓ 무료배송·오늘출발은 본문 텍스트 라인, 쿠폰만 뱃지 1개
- ✕ "유료회원 전용"용 새 보라 뱃지 신설
- ✓ 기존 그레이 뱃지에 텍스트만 "유료회원 전용"으로 변경
- ✕ 라벨에 black bg / outline / filled / underline 4종 형태 혼용
- ✓ 다수 노출 PLP는 outline / 단건 강조는 black bg — 2종 케이스 정의 후 일관 적용

#### 기본 severity 가이드
- 한 화면 컬러 뱃지 3종 이상 동시 노출 → 🟡
- 새 뱃지 형태 신설 제안 (기존으로 흡수 가능한데도) → 🟡
- 뱃지 1개 색상 weight 조정 의견 → 🟢

#### 한계
프로모션·기획전처럼 단기간만 노출되는 surface는 한시적 뱃지 추가 허용. 단, 종료 시 제거 보장 필요.

### 🔍 [visual] 3. 정보가 다 중요할수록 1~2개만 강조한다

- **카테고리**: visual
- **소스**: 크리틱 인덱스 C — Bongho·Luna (2024-04 ~ 2025-11)
- **신뢰도**: high

#### 발견
"이 정보도 중요, 저 정보도 중요"라며 다 노출·강조하면 결국 아무것도 안 보인다. **핵심 1~2개에 강조를 몰고, 나머지는 건조하게** 둔다.

#### 근거
- Luna: "이 정보들이 다 중요하다고 외치는 상황이니 기준 잡기가 어렵긴합니다... 그럼에도 제일 중요한 요소 1,2개 확실히 픽스, 강조 몰빵 + 그 외 요소는 건조하게 가보면 어떨까합니다 (텍스트만 넣되 컬러로 또는 weight로만 강조). 노란 BG는 시선이 분산되서 보기 어렵긴하네요." / Trend Seeker 피드는 "이미지에 집중시킨다. 정보의 볼륨을 줄인다" — 섬네일·상품명만 남기고 상품카드를 짧게.
- Bongho: "할인가, 기존가, 할인금액까지 노출되는 것이 맞는지 의문이 들어요. 필요한 정보만으로 압축하면 어떨까."

#### 적용 가이드
- 한 요소에 정보가 3개 이상 몰리면 "다 중요" 신호 — 우선순위를 강제로 매기고 1~2개만 강조한다.
- 강조는 색·배경보다 **weight·크기·위치**로 (인사이트 1, `principles.md` #4).
- 중복·파생 정보(할인가+기존가+할인금액)는 압축한다.

#### Bad ✕ / Good ✓
- ✕ ProductCard에 할인율 + 가격 + 별점 + 리뷰수 + 무료배송 뱃지 + 오늘출발 뱃지 + 쿠폰 뱃지 (강조 7개)
- ✓ ProductCard에 할인율 bold + 가격 bold + "무료배송 · ★ 4.8" 한 줄 (강조 2개)
- ✕ "할인가 1,290,000원 (기존가 1,890,000원, 할인 600,000원 적용)" — 가격 정보 3중 노출
- ✓ "32% 1,290,000원" — 할인율 + 적용가만
- ✕ 안내 박스 노란 배경 + 빨간 테두리 + 큰 폰트 + 느낌표 (강조 4중)
- ✓ 본문 weight bold 한 단어만으로 강조

#### 기본 severity 가이드
- 한 요소에 강조 5개 이상 → 🟡
- 중복 정보 (할인가+기존가+할인금액) 3중 노출 → 🟡
- 강조 한두 곳 조정 의견 → 🟢

#### 한계
SuperApp 진입 페이지·기획전 메인처럼 의도적으로 정보 밀도가 필요한 surface는 예외 (단 그 안에서도 1~2개 우선순위는 명시).

### 🔍 [visual] 4. 구분은 디바이더보다 여백으로

- **카테고리**: visual
- **소스**: 크리틱 인덱스 D — Ray (2024-01)
- **신뢰도**: medium

#### 발견
영역 구분에 선(divider)을 먼저 쓰지 않는다. **여백(spacing)만으로 해결되는지 먼저 본다.**

#### 근거
- Ray: "디바이더 없이 스페이싱 만으로 해결 가능하지 않을까요." / "스페이싱만 위 아래가 맞으면 덜 어색할 거 같긴하네요." / "디바이더를 꼭 써야하는 케이스들도 존재하니 정비해보면 어떨까 싶어요."

#### 적용 가이드
- 1차 시도는 항상 여백. 디바이더는 여백으로 안 될 때만.
- 디바이더가 꼭 필요한 케이스는 별도로 정의·정비해 일관되게 쓴다.
- `principles.md` #1(콘텐츠 우선, UI 조연)·`ux-design.md` 정보구조(그룹 구분은 보더보다 여백)와 동일선상.

#### Bad ✕ / Good ✓
- ✕ 모듈마다 위·아래 1px 디바이더 + 모듈 내 카드마다 0.5px 디바이더 (선이 화면을 잘게 자름)
- ✓ 모듈 사이 32px 여백, 카드 사이 12px 여백 — 선 없이 구분
- ✕ 카드 안 정보 섹션을 점선·실선으로 구분
- ✓ 정보 그룹 사이 8px 여백 + weight 차이로 위계
- ✕ 검색결과 안내 박스에 배경색 + 좌우 디바이더
- ✓ 안내 텍스트만 (배경·선 없음), 상하 spacing으로 본문과 구분

#### 기본 severity 가이드
- 모듈마다 디바이더 노출 / 카드 안 점선 분할 → 🟢 (구조적 큰 문제 아님)
- 디바이더가 강조 텍스트 contrast 저해 → 🟡
- 단순 디바이더 두께·색 조정 의견 → 🟢

#### 한계
표(table)·리스트 row처럼 **구조적으로 선이 의미를 만드는** 경우는 디바이더 필수. 데이터 시각화·약관 표는 예외.

### 🔍 [conversion] 6. 실험은 변수를 하나로 통제한다

- **카테고리**: conversion
- **소스**: 크리틱 인덱스 F — Luna·Ray (2024-01 ~ 2024-03)
- **신뢰도**: high

#### 발견
한 실험에 변수가 여러 개면 결과의 원인을 알 수 없다. **측정하려는 변수 하나만 남기고 나머지는 통일**한다.

#### 근거
- Luna: 오픈런딜 재실험 — "B는 2그리드... 상품카드가 커서 스크롤이 많이 발생함. 이것이 추가 탐색 축소에 영향을 미쳤을 것... 그리드를 통일하면 상품 노출 방식에 대한 변수가 제거됨. 따라서 결과를 더 정확히 파악할 수 있을 것." / "변수가 여러개라 실험 진행이 우려된다."
- Ray: "기본값을 이미지에 텍스트 안넣기로 가는게 변수를 통제하는 방향일 것 같아요."

#### 적용 가이드
- 실험 설계 시 "이번에 측정할 변수는 하나"라고 명시. 나머지 디자인 요소는 A/B 간 통일.
- 결과가 모호하면 변수가 섞였는지 먼저 의심하고, 통제한 재실험을 한다.
- 급진적 아이디어는 별도 실험으로 쪼갠다 (Luna: "유저 문제가 완전 달라지는거고... 별도 실험으로 쪼개서").

### 🔍 [mental-model] 7. 문제-솔루션 적합성을 먼저 검증한다

- **카테고리**: mental-model
- **소스**: 크리틱 인덱스 G — Yohan·Luna (2024-03 ~ 2024-08)
- **신뢰도**: high

#### 발견
디자인을 다듬기 전에 "이 솔루션이 진짜 그 문제를 푸는가"를 먼저 묻는다. 문제 공감과 솔루션 적합성은 별개다.

#### 근거

### 🔍 [visual] 14. 의미 카테고리가 같은 정보는 시각상도 가까이 둔다

- **카테고리**: visual
- **소스**: 2026-05-21 장바구니 도착예정일 추가 크리틱 — Yohan
- **신뢰도**: high

#### 발견
정보를 시각 위계(크기·weight)만으로 정렬하는 게 아니라 **의미 카테고리**(결제·배송·상품·메타)에 따라 시각적 인접성도 일치시킨다. Gestalt Proximity의 실무 응용 — *같은 의미는 가까이*.

#### 근거
- Yohan (2026-05-21 장바구니 도착예정일 ts 1779330336): *"특별인증가가 결제 관련된 정보이니 특별인증가 뱃지를 금액 근처로 이동을 해야하나 그런 고민도 됩니다."* — 위계 조정이 아닌 **의미 그룹 재배치** 제안.
- visual-design.md Gestalt Proximity 원리의 actionable 적용.

#### 적용 가이드 — 3단계

**Step 1. 카테고리 식별** — 한 카드/화면의 정보 요소를 의미 그룹으로 분류

화면별 카테고리 예시 (`domains/<screen>/policies/`에 화면별 정의):

| 화면 | 의미 카테고리 |
|---|---|
| **Cart** | 결제(가격·할인·특별인증가·쿠폰) / 배송(도착예정일·오늘출발·배송비) / 상품 메타(상품명·옵션·브랜드) |
| **PDP** | 상품 본체(이미지·이름) / 가격·혜택 / 배송 / 리뷰·콘텐츠 / 액션(스크랩·구매) |
| **Search SRP** | 검색 의도 / 결과 본체(섬네일·상품명·가격) / 부가(별점·태그·뱃지) |
| **Mypage** | 정체성(프로필·아바타) / 활동(스크랩·콘텐츠) / 설정·계정 |

> 화면별 정확한 카테고리는 도메인 정책에서 정의. 위는 기본값.

**Step 2. 시각 인접성 검증** — 같은 카테고리 elements가 시각상도 가까이 있는가?

**Step 3. 재배치** — 흩어져 있으면 그룹 단위로 재배치. 카테고리 사이는 여백·디바이더로 분리.

#### Bad ✕ / Good ✓

**Cart 카드 예시:**
- ✕ 상품명 → 도착예정일 → 가격 → 특별인증가 → 옵션
  - 배송 정보(도착예정일)가 가격을 가운데 두고 분리됨
  - 결제 결정 시 가격·할인·특별인증가를 한눈에 못 봄
- ✓ [상품 메타] 상품명·옵션 → [결제] 가격·할인·특별인증가 → [배송] 도착예정일·오늘출발
  - 결제 결정 정보가 한 그룹으로 묶임
  - 사용자는 "이 상품 살까" → "얼마 내야 하나" → "언제 와?" 자연스러운 시선 흐름

**PDP 예시:**
- ✕ 가격 → 리뷰 → 배송 정보 → 할인쿠폰 (혜택과 가격이 분리, 리뷰가 사이에)
- ✓ [상품] 이미지·이름 → [가격·혜택] 가격·할인·쿠폰·특별인증가 → [배송] 도착·배송비 → [리뷰] → [액션] CTA

#### Gestalt 근거

- **Proximity** (근접성): 가까운 요소는 한 그룹으로 지각
- **Common Region** (공동 영역): 같은 영역·배경 안의 요소는 한 그룹
- **Similarity** (유사성): 같은 스타일(weight·색·아이콘)도 카테고리 신호로 작동

`visual-design.md` Gestalt 6원리 참조.

#### 기본 severity 가이드

- 결제 정보가 배송·메타 사이에 흩어져 **결제 결정 흐름 깨짐** → 🟡
- 카테고리 식별 시도 없이 임의 배치 → 🟡
- 단순 인접성 미세 조정 의견 → 🟢

#### 한계
의미 카테고리 정의는 surface마다 다름. **화면별 카테고리는 `domains/<screen>/policies/` 에 정의** — 그 정책이 1차 권위, 위 표는 정책이 없을 때 fallback.

### 🔍 [conversion] E1. 랭커·추천은 신규 시그널 추가보다 "저성능 시그널 제거"가 더 큰 lift

- **소스 실험**: 홈피드 랭커 정리 (손석우 2024-08·11-26·12-30) · PDP 추천 임베딩 유사도 실패 → 행동 시퀀스 graph randomwalk win (2025) · Store-PLP AutoML 가중치만 조정 (Bobby 2024-08)
- **신뢰도**: high

#### 발견
랭커·추천 가설을 세울 때 "더 좋은 신호를 추가하면 좋아진다"는 직관이 자주 빗나간다. **이미 들어가 있는 약한 신호를 제거**하는 것이 신규 모델·시그널 도입보다 안전하게 lift를 만든다.

#### 근거
- 손석우 (Viewer 홈피드 2024-08-08): 화이트리스트·인기순·라이프토픽 프로듀서 *제거* + 헤비크리에이터 추가 → Winner D
- 손석우 (시즌 콘텐츠 2024-12-30): "성능이 좋지 않은 프로듀서 제거" 정책 효과 재확인 — CTR/Impression/Click count/다양성 모두 향상
- 임베딩 유사도 추천 (2025): "기대하던 업사이드를 만들어내지 못해 A안으로 롤백" → 다음 실험에서 representational space → behavioral space로 피벗해 win
- Bobby (Store-PLP 2024-08-23): AutoML 가중치만 조정으로 win — 새 feature 없이도 충분

#### 적용 가이드
- 랭커 audit 정례화 (분기 1회): "현재 weight 중 lift에 기여 안 하는 것"부터 먼저 본다.
- 모델 swap·새 feature는 마지막 lever. 첫 lever는 weight tuning + 약한 signal 제거.
- "유사도(상품 representation)"보다 "사용자 다음 행동(behavioral sequence)" 신호가 conversion KPI에 더 잘 맞음.

### 🔍 [conversion] E2. 인지 lift는 mid-funnel만 들어올린다 — output 도달은 다단계로 분리 검증

- **소스 실험**: 묶음배송 인지 (장건준 2024-11-19) · 1grid vs 2grid (수리 2024-12-23) · 특가 UX 베어 (2024-11-12) · 글린다 할인가 조회 (장건준 2025-11-05) · 마이페이지 최근 방문 탭 (Edwards 2024-07-29)
- **신뢰도**: high

#### 발견
"인지를 강화하면 구매까지 늘어날 것"이라는 가설은 실험에서 자주 일부만 성립한다. **인지 → 클릭 → 조회**까지는 자주 lift되지만, **output(Buyer Conversion / GMV)** 도달은 단발 실험으로 거의 안 옮겨진다. 다단계 iteration plan을 ABT 종료 전에 미리 그려야 한다.

#### 근거
- 묶음배송 인지 (장건준): PLP 내 상품조회 +17.21%, PDP→묶음배송 PV +172%, 그러나 "output 증가 달성을 위해서는 몇차례의 이터레이션이 필요"
- 1grid UI (수리): "더 많은 고객이 상품을 탐색했습니다 ... 다만 이 결과가 구매까지 유의하게 이어지지는 않았습니다"
- 특가 UX (베어): Buyer Conversion +1.14% / 상품 클릭 +0.35%, 그러나 "GMV, PV에 영향을 미칠정도는 아니었습니다 ... 특가 상품은 객단가가 낮아 매출 증대에 기여하기에는 성장 규모가 부족"
- 글린다 할인가 조회: +8.89% 조회 lift, 그러나 "기대했던 구매 전환율 상승까지는 이어지지 않았음 ... 빠른 후속 개선(Iteration) 필요"
- 마이페이지 최근 방문 탭: 진입은 늘었으나 retention 미관측 → "진입 자체가 retention의 lead indicator가 아닐 수 있음"

#### 적용 가이드
- 인지 강화 실험은 **success metric을 PDP/카트 직전까지 멀리** 잡는다. 클릭·진입을 success로 두면 잘못된 winner를 만들 위험.
- ABT 시작 전 "이 실험이 단독으로 output까지 갈 수 있는가?"를 자문. No면 multi-step roadmap부터 그린다.
- AOV·ASP를 보조 지표로 항상 포함 (특가/할인 실험). Buyer Count↑ + GMV flat은 객단가 하락 신호.

### 🔍 [conversion] E3. 신규 광고·모듈 인벤토리는 카니발리제이션을 사전·동시에 측정

- **소스 실험**: 스타일링샷 신규 광고 인벤토리 (2025-06-13 롤백) · PDP 하단 광고 (Kiana 2024-09 A win) · 인오가닉 백버튼→쇼핑홈 (2024-06-20 PDP -7.5억 cannibal)
- **신뢰도**: high

#### 발견
신규 광고/추천 인벤토리 추가는 **항상 기존 인벤토리·인접 surface와의 카니발리제이션이 동반**된다. 단일 surface KPI lift만 보고 launch하면 site-wide net은 음(-)일 수 있다.

#### 근거
- 스타일링샷 신규 광고 (2025-06): 유입고객당 합계이익 -3% → 폐기. "신규 추가된 지면에 기존재하던 상품광고와 카니발이 발생하면서, 광고 CVR 및 전환거래액이 감소"
- PDP 하단 광고 (Kiana 2024-09): 합계이익 lift 없음 + 구매자 전환율 -0.27% → A win (보류)
- 인오가닉 백버튼→쇼핑홈 (2024-06): "PDP와 카니발이 나는 경향이 관측됨 ... PDP 기여거래 -7.5억, 쇼핑홈 first 기여거래 +6.2억"

#### 적용 가이드
- 광고/모듈 신규 인벤토리 ABT 설계 시 **page-pair 분포·인접 surface 기여거래 변화**를 success metric에 명시.
- CVR 차이가 큰 광고 형식(상품광고 vs 스타일링샷 등) 간 인벤토리 공존은 cannibal 위험이 크다 — 형식별 슬롯 분리.
- "수익성 절대값"이 가드레일 하락을 능가하지 않으면 winner로 안 본다.

### 🔍 [visual] E4. 정보성 모듈은 "시스템 UI 톤"으로 — 배너 톤은 광고로 인지되어 회피된다

- **소스 실험**: 스마트스토어 인지 영역 확대 (2024-11-06, Yohan/Ilwon 코멘트) · 글로벌 온보딩 (2024-07-03 가치 전달이 lift) · 검색결과 없음 페이지 개선 (2025-06)
- **신뢰도**: medium

#### 발견
배너 형태(배경 이미지·색상)로 정보 모듈을 만들면 사용자는 **광고로 인지해 회피**한다. 정보 신뢰가 목적이면 **시스템 UI 톤(흰 배경, 시스템 폰트, 아이콘만)** 으로 디자인해야 한다.

#### 근거
- Yohan (스마트스토어 lesson): "배너에 대해서 오늘의집 프로덕트 전체에서 받았던 다양한 인풋은 *광고성으로 인지된다*라는 의견들이 지배적이었습니다. 정보성은 *시스템에서 제공하는 것처럼 인지되도록* 하는게 더 낫다는 판단이에요"
- 글로벌 온보딩 (2024-07-03): "서비스 & 기능의 *가치를 잘 소통*하는 것만으로도 행동 변화가 일어난 사례 ... 우선 Ohouse의 서비스 자체를 명확하게 보여주고 소개하는 것이 중요하다"
- 검색결과 없음 (2025-06): "유저가 찾는 검색결과가 없더라도 검색 의도에 적절한 상품이나 사진을 제공한다면, 통합검색의 이탈을 줄이고 검색 내 소비를 늘릴 수 있을 것" — Empty state도 정보 모듈로 작동

#### 적용 가이드
- 정보성 알림·안내·CTA 박스에는 컬러 배경·이미지 KV를 쓰지 않는다. 흰 배경 + 시스템 폰트 + 보조 아이콘만.
- Empty state는 막다른 길이 아니라 **의도 우회 surface**. 안내 + 다음 행동(추천/대체)을 함께.
- `design-insight.md` §1 #1·#3과 함께 적용 — 색은 의도가 분명할 때만, 정보는 1~2개만 강조.

### 🔍 [conversion] E5. 동의·구독 UX는 메시지를 좁힐수록 전환율이 폭증한다

- **소스 실험**: 스크랩 상품 소식 알림 신청 (XPC 1228, 리지 2024-11-08) · 마케팅 푸시 수신 동의 (패트릭 2024-07) · LE Activation (테리 2025-11-13) · 맞춤정보 v2 라이프이벤트 (테리 2025-11-13, 9.2x)
- **신뢰도**: high

#### 발견
동의·구독·옵트인 UX에서 "여러 혜택을 종합 소개"하면 전환율이 떨어진다. **단일 가치 1개로 메시지를 좁히면** 전환율이 +100%대로 폭증한다.

#### 근거
- 스크랩 알림 신청 (XPC 1228): B(가격 할인만 강조) vs C(다양 정보) — "B안에서 C안 대비 알림 신청 동의율 +142%(+14.7%p) 상승" / "고객들이 가장 받고 싶어 하는 알림은 할인 소식일 것이다. 결론: 검증" / "B안 25.2% vs C안 10.4%"
- LE 입력 완료율 (테리 2025-11-13): 최대 5만 포인트 incentive → 0.5% → 4.6% (9.2배). 데이터 콜드스타트가 critical할 때 incentive ROI가 매우 큼
- 이사 설문 (2025-05-17): 10p 리워드 → 응답률 +68%, 월 8만명 응답 + Yes 즉시 이사클럽 라우팅으로 tradeoff 최소화

#### 적용 가이드
- 옵트인 UX에서 메시지 후보가 3개 이상이면 가장 강한 1개만 남긴다 — "할인" 같은 명확한 outcome 표현.
- 첫 시도는 단일 가치, 그 다음 iteration에서 segment별 메시지 분기.
- 데이터 콜드스타트 영역(LE·취향·공간)에서는 큰 incentive를 망설이지 않는다 — ROI가 다른 영역의 10배 이상.

### 🔍 [pattern] E6. site-wide KPI에 갇히지 말고 segment·participant-level conversion까지 본다

- **소스 실험**: 신브랜드홈 MVP (Conan 2024-10-10) · 주문목록 검색 (데이지 2025-09-29) · 스페셜 오늘의딜 상품카드 (지수 2025-10-22) · 오늘의딜 ATF (지수 2025-10-12)
- **신뢰도**: high

#### 발견
사이트 전체 GMV는 큰 노이즈로 작은 surface 변경의 임팩트를 잘 보여주지 못한다. **실험 참여자(=해당 화면을 본 유저) 또는 매장·카테고리 단위 segment의 conversion이 더 정확한 의사결정 단위**다.

#### 근거
- 신브랜드홈 MVP (Conan): "런칭 조건인 가드레일 지표(전체 GMV/C와 buyer conversion)를 방어하는 것을 넘어, 실험참여자(=브랜드홈을 한번이라도 방문한 유저)의 buyer conversion을 유의미하게 +1.29% 상승시킬 수 있었습니다 ... 거래액지표도 B안이 더 높았으나 아쉽게 통계적 유의미성까진 확보하지 못했습니다. 그럼에도 support metrics(브랜드홈 기여 GMV, 브랜드홈 방문횟수)이 큰 폭으로 증가"
- 주문목록 검색 (데이지): "PDP 진입률은 감소하였으나 재구매율은 상승" → B win
- 스페셜 오늘의딜 (지수): "site-wide/매장내에서 유의미하게 상승이 없었으나, PDP 전환율의 경우 오늘의딜 매장 내에서 +2.25% 개선" → 부분 win 롤아웃
- 오늘의딜 ATF (지수): "XPC 지표, 오프라인 분석 모두 p-value가 유의미하게 떨어지지 않아 증분이 없다고 결론났으나 고객 경험 개선 및 이터레이션을 위해 B로 종료"

#### 적용 가이드
- 모든 surface ABT에 **participant-level conversion**을 default sub-metric으로.
- 매장/카테고리 surface 실험은 **segment-local KPI를 primary**로 둔다. site-wide는 가드레일.
- user lifecycle 지표(재구매율·D7 retention)는 short-term funnel 지표와 함께 봐야 winner 판정 가능.

### 🔍 [pattern] E7. 검증된 UX 패턴은 인접 surface로 거의 그대로 이식된다

- **소스 실험**: PDP 하단 IIF 적용 (2024-04, exp 1011) · 통합검색 콘텐츠 컬렉션 추가 (2024-06-14) · Viewer next-watch (정재용 2024-11-13) · 글린다 배너형 UI (장건준 2024-11-04)
- **신뢰도**: medium

#### 발견
한 화면에서 검증된 UX 패턴(IIF 무한피드·캐러셀·tap-friendly 카드)은 인접 추천 영역·다른 화면으로 옮겨도 거의 동일한 lift를 재현한다.

#### 근거
- PDP 하단 IIF (2024-04, Winner C): "PDP 조회자 전환율 +1.65%, PDP 내 상품 조회수 +40.13%" — IIF 패턴을 PDP 하단으로 이식
- 통검 콘텐츠 컬렉션 (2024-06): "검색 콘텐츠 조회 유저 전환율 37.12% → 38.09% (+2.63%, p=0)" — 검색에 콘텐츠 컬렉션 모듈 추가
- Viewer next-watch (2024-11): "앱 전체에서 콘텐츠 소비량 증가, Avg. Content View +1.65%, CDP의 Content View +3.31%" — player 내부 패턴이 site-wide consumption까지
- 글린다 배너형 UI (2024-11-04): "구매자 전환율 +19.86%, 거래액 +14.96%" — 다른 promo surface에도 배너형 UI 가치 명시 적용 가능

#### 적용 가이드
- 새 화면 설계 시 "이 화면과 가장 유사한 surface에서 win한 패턴은 무엇인가?"를 먼저 확인 — 발명보다 이식.
- 이식한 패턴은 첫 실험에서 가장 강한 mid-funnel 지표(클릭/조회)부터 본다.
- 단, surface별 사용자 의도가 다른 경우(grid 변경 등)는 이식이 안 통할 수 있음 — `E2` 함께 고려.

---

### 🔄 §2 승격 기준 (실험 → 인사이트)

1. **2+ 실험에서 같은 발견 반복** (필수)
2. **일반 원리로 추출 가능** (단일 화면을 넘는 원리)
3. **새 정책·디자인 결정의 근거가 됨**

**승격 안 함**: 단발 win, 단순 metric 공시, 한 화면에서만 유효한 결과. 그 실험들은 도메인 `experiments/`에 원본 보존.

새 인사이트를 추가하려면 위 양식(발견·근거·적용 가이드)으로 이 섹션에 append.

## 🏷️ 카테고리 정의

- **behavior** — 사용자가 실제로 어떻게 행동하는가
- **mental-model** — 사용자가 어떻게 이해하는가
- **conversion** — 전환률·실험 설계 패턴
- **visual** — 색·컴포넌트·레이아웃 등 시각 판단
- **accessibility** — 접근성 발견
- **qualitative** — 인터뷰·관찰·카피에서 나온 정성 발견
- **pattern** — 여러 화면에서 반복되는 일반 패턴
