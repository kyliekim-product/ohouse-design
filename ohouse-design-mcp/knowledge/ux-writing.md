# UX Writing — 오늘의집 라이팅 가이드

오늘의집 카피·문구의 톤·구조·표기 규칙을 한 곳에 정리. 자동화는 `.claude/skills/writing-bot/` 스킬이 담당하고, **이 문서는 사람이 보는 판단 기준**.

> `./ux-design.md` 마이크로카피 톤 + `./design-insight.md` 인사이트 #11(카피는 사실 + 행동 제안, 부정 표현 지양)의 상세 버전.

---

## 🎙️ 기본 톤 (Tone of Voice)

오늘의집 라이팅은 **친근하지만 절제된** 톤. 친구처럼 가깝지만 호들갑 떨지 않는다.

| Do | Don't |
|---|---|
| 해요체 기본 / 공식 안내는 합쇼체 혼용 | 반말·명령조 |
| 누구나 이해할 쉬운 표현 | 전문 용어·어려운 한자어 |
| 명확하고 구체적인 정보 | 과장·애매한 표현 |
| 동사 우선 ("저장") | 명사형 ("저장하기") |

### 항상 지키는 4가지

1. **호칭 금지**: 절대 고객을 "당신"이라고 부르지 않는다.
2. **브랜드명 직접 언급 금지** (앱푸시·배너): "오늘의집" 단어 자체를 본문에 노출하지 않는다.
3. **밈·인터넷 신조어 금지**: "~할 각", "~임?", "헉", "역대급", "실화?", "대박" 등.
4. **오늘의집 용어집 보존**: 집들이, 나만의 패키지, 스크랩 등은 변형하지 않는다.

## 📐 일반 라이팅 룰

- **논리적이고 자연스럽게** 읽히는 문장. 초안의 의미를 유실하지 않는다.
- **쉼표 최소화** — 꼭 필요한 경우 외 사용 안 함.
- **한 문장에 하나의 메시지** — 둘 이상이면 문장 분리.
- **불필요한 수식어·피동형 제거**.
- **같은 단어 반복 금지**.
- **이중 부정 금지** — "안 받지 않을까요?" X.

## 💬 메시지 유형별 톤 (UI 메시지 5종)

| 유형 | 톤 | 구조 |
|---|---|---|
| **Error** 오류 | 합쇼체, 차분 | 원인 + 해결책 |
| **Confirm** 확인 | 해요체 | 결과 안내 + 선택 요청 |
| **Info** 안내 | 해요체 | 상황 설명 |
| **Success** 성공 | 해요체, 담백 | 완료 안내 + 다음 행동 |
| **Warning** 경고 | 단호 | 위험 강조 |

→ `./ux-design.md` 상태 표현 5종(default/empty/loading/error/offline)과 매칭.

### 카피 작성의 황금률 (`design-insight.md` #11)

1. **객관적 현 상태**를 먼저
2. **다음 행동 제안**으로 끝
3. 부정·불확실·단정형 금지
4. 기존 안내 문구의 서술 방식과 통일

```
❌ "결제할 수 없습니다."          (단정·부정형)
❌ "오류가 발생했습니다."          (사유·행동 불명)
❌ "가격이 다를 수 있어요."        (불확실형)

✅ "결제가 진행되지 않았어요. 카드 정보를 다시 확인해 주세요."
✅ "아직 담은 상품이 없어요. 마음에 드는 상품을 찾아보세요."
✅ "교환 요청이 택배사에 접수되어 교환 철회를 할 수 없어요."
```

## 🧱 UI 요소별 가이드

### 버튼 (Button)

- **2~6자** 한국어 길이 기준
- 동사 우선 — "확인", "저장", "다시 결제하기"
- 보조 버튼은 다음 행동을 제안 — "취소" → "결제 정보 변경", "결제 정보 다시 입력"

### 빈 상태 (Empty)

- **친근 톤** — "아직 ~없어요. ~해보세요"
- 일러스트 + 한 줄 설명 + 다음 액션 CTA (`./ux-design.md` 상태 표현)
- "데이터가 없습니다" 한 줄 금지

### 스낵바 (Snackbar) / 툴팁 (Tooltip)

- 2~4초 노출, 단일 액션 슬롯 1개
- 담백한 안내 + 필요 시 되돌리기/취소 액션

### 모달·바텀시트

- 헤더: 한 줄 명사구 또는 짧은 질문 — "삭제할까요?"
- 본문: 결과 설명 + 선택지 안내
- 액션 버튼: 긍정·부정 명확히 (둘 다 같은 강조 X)

## 📱 앱푸시 (Push Notification)

오늘의집 앱 알림으로 전달되는 메시지. 재방문·행동 유도가 목적.

### 필수 제약

- **제목**: 21자 이내, 이모지 1개까지
- **본문**: 32자 이내, **반드시 `(광고)`로 시작**
- **이모지**: 제목 또는 본문 중 한 곳에만 1개 (중복 금지)
- **제목·본문 어미 다르게** 구성
- **호칭 "당신" 금지** / **"오늘의집" 직접 언급 금지**
- **개인화** (O2O 제외): 본문에서 `{{custom_attribute.${nickname} | default : "고객"}}님`

### 톤

- 궁금증 자극 — 단, 과장·밈·자극 금지
- 제목은 후킹, 본문은 궁금증 해소

```
❌ "헉! 역대급 세일!"
✅ "오늘만 무료배송, 놓치지 마세요"
```

## 🎨 배너 카피 (Banner Copy)

화면 진입의 첫 인상. 구좌별 글자 수·톤이 다르다.

### 공통 룰

- **브랜드명·기획전명 직접 언급 금지**
- 2줄 카피는 두 줄의 의미가 **연결**되도록
- 같은 단어 중복 금지
- 마침표 금지, **느낌표 최대 1회**
- 고객 지칭("당신", "유저") 금지

### 구좌별 가이드

| 구좌 | 길이 | 톤 |
|---|---|---|
| **쇼핑홈 IIF** | 1줄, 공백 포함 10자 내외 (최대 15자) | 브랜드 포지셔닝·상품 특성 중심. **혜택 직접 언급 금지** |
| **공통홈피드** | 2줄, 각 10자 이내, 줄 간 글자 수 차이 5자 이내 | 감성적·철학적 명사구. 혜택 언급 금지 |
| **Binary 홈배너 ver.1** | 1줄 10자 이내 + 혜택 병기 가능 | 절제된 감성 |
| **Binary 홈배너 ver.2** | 2줄 각 10자 이내, 혜택 없음 | 일상 장면 묘사, 압박형 금지 |

### 패턴 베리에이션

숫자형 / 의문형 / 명사구형 / 시간압박형 / 철학 강조형 / 혜택 강조형.

## 🎁 기획전 (Exhibition)

기획전 유형마다 정해진 구조가 있다. 감성은 살리되 **과장하지 않는다**.

### 브랜드위크 (Brand Week)

- 구조: **INTRO → SELECTION**
- INTRO: 2~3문장, 총 40~80자, 합쇼체
- SELECTION 소타이틀: 18자 이내 / 내용: 소구 포인트 3개, 56자 이내 명사구
- 섹션 소개 카피: 6~15자, 5개 이상 리스트 제안

### 브랜드캐스트

- 타이틀: `[브랜드명] + [할인율]`
- 인트로: 3~4문장, 30~50자, **반드시 "[브랜드명] 브랜드입니다."로 끝맺음**
  - O: "일리 브랜드입니다."
  - X: "일리입니다."

### Binary Report

- 구조: 타이틀 → 인트로 → 트렌드 소개 (5~7개 브랜드, 각 2~3문장)
- **인트로 고정 문구**: "바이너리샵 MD들이 고독하고 은밀하게 품어두는 주간 트렌드 리포트입니다."

### Binary Bookmark

- 구조: 타이틀 → Recommend (3~4개) → About us (120~220자)
- 타이틀: `[핵심 수식어], [브랜드명]` 구조, **종결어미 금지**

### Ohouse Edition

- 구조: 타이틀 → ITEM 4개 → BENEFIT → MD COMMENT → DETAIL → BRAND INTERVIEW → REVIEW
- 타이틀: 형용구 + 제품명, 25자 이내
- ITEM: 핵심 소구 4개, 각 25자 이내 명사구
- MD COMMENT: 100~200자, 해요체, 직접 써본 듯한 톤
- BRAND INTERVIEW: 질문 3개 + 답변 각 200~500자, 브랜드 철학 중심
- REVIEW: 사용자 후기 기반 2줄, 해요체
- **톤**: 해요체 + 합쇼체 혼용, 실용 정보 중심

### 라이터 페르소나 (선택)

- **지나** — 고감도, 자기다움, 스토리 중심
- **세아** — 감성적, 발견형, 우연성 강조
- **현정** — 실용적, 신뢰, 검증 강조

## 🛋️ layer 브랜드 PDP

layer는 **제품 스펙이 아니라 삶과 공간 속에서의 기준**을 제안하는 브랜드. 카피도 그 결을 따른다.

### 코어 구조

1. 사용 장면·상황 먼저 제시
2. 제품이 해결하는 지점 연결
3. 필요 시 기능·구조·소재를 뒤에

**기능·스펙으로 문장을 시작하지 않는다.** 한 문장에 하나의 메시지, **15~40자 이내**.

### 톤 & 금지 표현

- **반드시 해요체.** 쉼표 최소화.
- 금지: **최고, 완벽한, 혁신적인, 압도적인, 궁극의, 프리미엄**
- 전문 용어는 사용 경험 중심으로 풀어쓴다:
  - "고밀도 구조 설계" → "오래 사용해도 안정적인 구조예요"
  - "인체공학적 설계" → "편안하게 사용할 수 있도록 구조를 설계했어요"

### 수정 예시

```
수정 전: 고밀도 구조 설계를 적용했습니다.
수정 후: 오래 사용해도 안정적인 구조예요.
이유:    전문 용어를 사용 경험 중심으로 풀어 표현.
```

## 📅 날짜·시간 표기

### 날짜 축약형 (마침표 구분, 붙여쓰기)

- 올해 게시물: `04.19`
- 연도 포함: `2024.12.06`
- 요일: 기본 미표기. 필요 시 `04.19 (수)` (괄호 한 글자)
- 한 자릿수 일은 `0n`으로 (`04.19`, `04.07`)
- 연도 줄여쓰기 금지 (`24.12.06` X)
- 예외: 커머스 배송일은 슬래시 허용 — `배송중·11/27(월) 도착 예정`

### 날짜 일반형 (강조 시)

- `2023년 4월 19일 (수)` — 연/월/일/요일 모두, 항목 간 띄어쓰기

### 시간

- 24시간: `14:30` (쌍점 구분, 붙여쓰기)
- 12시간: `2:30 PM` (오전/오후 함께)

### 업로드 시간 표기

| 경과 시간 | 표기 |
|---|---|
| 1분 미만 | 방금 |
| 1분 ~ 1시간 | N분 |
| 1시간 ~ 24시간 | N시간 |
| 24시간 ~ 8일 | N일 |
| 8일 이상 | 업로드 날짜 |

## 💰 숫자·금액 표기

### 기본

- 천 단위: 쉼표로 구분 — `9,900` / `13,000`
- 숫자 + 단위: **붙여쓰기** — `9,900원`, `20%`, `79.3㎡`
- 소수점: **1자리까지만**
- "만"·"원" 붙여쓰기 — `1만원`, `10만원`, `100만원`

### 줄임 표기 (좁은 영역 — 스크랩 수·조회 수)

- `K` = 1,000 / `M` = 1,000,000
- 소수점 1자리까지
- 예: `3,526` → `3.5K` / `11,000` → `11K` / `7,000,000` → `7M`

### 수량 한정 표현

| 의미 | 표기 |
|---|---|
| 최대치 | `~30%까지` 또는 `최대 30% 할인` |
| 최소치 | `최소 3개 이상` |
| 대략 | `약 1,000명 참여` |
| 이상/이하 | `5만원 이상` / `10세 이하` |
| 시작 기준 | `9,900원부터` |

**물결표(`~`) 단독 사용 금지** — 반드시 "까지"를 붙인다.

## ✅ 응답 전 체크리스트

문구를 내보내기 전 다음 5축을 자체 검수.

### 가치·혜택을 명확하게 전달했는가
- 기대 이점을 앞부분에 강조했는가
- 구체적인 숫자를 활용했는가
- "고객이 얻을 수 있는 혜택" 중심으로 썼는가
- "해야 한다"보다 "하면 좋다"로 표현했는가

### 메시지가 명확하고 직관적인가
- 한 문장에 하나의 메시지만 담았는가
- 불필요한 수식어를 삭제했는가
- 같은 단어가 반복되지 않았는가
- 불필요한 피동형(수동태)을 쓰지 않았는가

### 사용자가 무엇을 해야 할지 명확한가
- 다음 행동을 명확하게 안내했는가
- 문제 상황 시 구체적인 해결책을 제시했는가
- 강요하지 않고 자연스럽게 동기 부여했는가

### 긍정적인 경험을 제공하는가
- 이중 부정 질문이 없는가
- 부정적인 감정을 일으키는 단어가 없는가
- 과장 없이 담백한가
- 절대적 표현 ("No.1", "꼭 사야 해요") 대신 객관적 사실인가

### 기본 표기 규칙
- 맞춤법·문법·표기 규칙 확인
- 용어집 용어 그대로 사용
- 날짜·숫자·금액 표기 규칙 준수
