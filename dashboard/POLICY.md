# 도메인 운영 정책

`ohouse-design-mcp/domains/` 의 화면 도메인을 **누가·언제·무엇을** 관리하는지에 대한 규칙.
현황 데이터는 [DASHBOARD.md](./DASHBOARD.md)(자동 생성)에서 확인한다.

---

## 1. 오너십

- **도메인 = 화면**. 한 사람이 여러 화면을 담당할 수 있다.
- 작업을 시작하는 사람이 해당 화면의 오너가 된다 → `ohouse-design-mcp/domains/<화면>/README.md` frontmatter `owner` 와 본문 오너십 섹션을 본인으로 갱신.
- 오너 변경 시 함께 갱신할 파일: `domains/<화면>/README.md` · `domains/README.md` 표 · `OWNERS.md` · `.github/CODEOWNERS`.
- 마스터 표는 `ohouse-design-mcp/OWNERS.md`.

## 2. 신선도 기준 (방치 판단)

마지막 커밋 경과일 기준. 대시보드 상태 이모지와 동일하다.

| 상태 | 기준 | 의미 / 액션 |
|:--:|---|---|
| 🟢 | ≤ 14일 | 활발 — 별도 액션 없음 |
| 🟡 | ≤ 30일 | 점검 — 오너가 진행 상황 1줄 코멘트 |
| 🟠 | ≤ 90일 | 방치 주의 — 오너에게 리마인드, 필요 시 재배정 |
| 🔴 | > 90일 | 장기 방치 — 운영자(요한)가 오너 재확인 / 아카이브 검토 |
| 📭 | 산출물 0 | 폴더만 존재 — 착수 대상. 오너 미정이면 우선순위 협의 |
| ⚫ | 커밋 없음 | git 히스토리 없음 — 새 폴더이거나 미커밋 |

> 기준 일수를 바꾸려면 `generate.mjs` 의 `FRESH / WARN / STALE` 상수와 이 표를 함께 수정한다.

## 3. 업데이트 의무

- 화면 작업 시 4개 서브폴더(`screens` / `components` / `policies` / `experiments`)의 `INDEX.md` 에 결과 1줄을 남긴다.
- 변경은 PR 로 올린다 (`main` 직접 push 금지). 리뷰어는 요한 + (오너 있는 화면이면 그 오너).
- 커밋 메시지 = "무엇을 했는지"의 1차 기록. 대시보드의 "최근 작업" 컬럼이 이 메시지를 그대로 보여주므로 의미 있게 작성한다.

## 4. 운영 리듬

- **주 1회**: `node dashboard/generate.mjs` 실행 → DASHBOARD.md 커밋. 🟠🔴 방치 도메인을 오너에게 공유.
- **월 1회**: 오너 미지정(TBD) · 산출물 없음 도메인 점검, 우선순위 재조정.
- 운영 담당: 요한 (`U06PVRTFW4D`).

## 5. 데이터 소스 한계

- 신선도·수정자·커밋수는 **git 히스토리** 기반 → 커밋되지 않은 작업은 반영되지 않는다.
- 오너는 README frontmatter `owner` 한 줄에서 읽는다 → 표기가 없으면 `TBD`.
- 폴더 rename 시 git 이력이 따라오지만, 경로 변경은 `generate.mjs` 의 `MCP` 상수에 반영해야 한다.
